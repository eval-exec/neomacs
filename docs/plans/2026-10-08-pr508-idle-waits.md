# Issue #476 and PR #508: idle epochs and wait completion

## Scope and GNU reference

The original report involves macOS ARM64, FrankenTerm and a full Doom
configuration. That exact environment has not been reproduced on this Linux
host. Process traffic alone is therefore a regression scenario, not an
established explanation for the original report.

GNU `keyboard.c:2847` starts idleness only for reads without an end time;
`:3083` stops it under the same condition. `timer_start_idle` at `:4692` is
idempotent, `timer_stop_idle` invalidates the epoch, and `timer_resume_idle`
restores the previous epoch for internal events. `process.c` services timers
while waiting and checks keyboard input after callbacks.

The [Idle Timers manual](https://www.gnu.org/software/emacs/manual/html_node/elisp/Idle-Timers.html)
requires subprocess activity to preserve the idle clock. The
[Reading One Event manual](https://www.gnu.org/software/emacs/manual/html_node/elisp/Reading-One-Event.html)
requires a read with a timeout to preserve its caller's existing idle state,
including when invoked by an idle callback.

## Reproduction and boundaries

Before applying the existing PR fix, nextest reproduced two failures:

- `command_input_preempts_self_rescheduling_zero_idle_timer_between_batches`:
  actual `Interrupted`, expected `InputPending`.
- `presentation_retirement_does_not_preempt_timer_batches`:
  actual `Interrupted`, expected `DeadlineElapsed`.

The service outcome was captured before redisplay callbacks could enqueue
input. Completion must recheck input after callbacks, before selecting a less
important completion. Display maintenance may yield an unbounded command read,
but a bounded read must retain its deadline contract.

The existing process-output regression checks that an idle callback fires
before the eventual user input and that process output was accepted. It does
not measure a precise 50 ms firing deadline.

Additional timed-read regressions reproduced idle loss at immediate timeout,
after blocking to a deadline, and when real input arrives. The non-idle timed
read and ordinary unbounded-input controls passed. A first typed correction
made those five tests pass, then independent review found direct and
wait-serviced ignored-event handlers that could still stop or resurrect an
idle epoch.

The inherited runtime independently failed the real TUI and GUI fixtures:
`current-idle-time` was approximately one second before a timed read inside an
idle callback and nil afterward. Both fixtures recorded live subprocess output
and ordinary timer ticks. GNU passed the terminal fixture with the idle epoch
increasing across the timed read. These probes reproduce a concrete GNU
mismatch, while the original config's complete starvation remains unverified.

 Test boundaries are the Lisp reading/timer APIs, command-input wait,
real terminal input and real GUI presentation. Temporary evidence stays under
`./tmp/`; Rust test execution uses `cargo nextest`.

## Long-term abstraction

Keep three concepts separate: the idle epoch, work serviced during a wait, and
the reason a wait completes. Timer callbacks, process output and presentation
acknowledgements are work, not user activity. An ordinary event read can own
idle transitions; a timed event read must preserve its caller's state.

Retain typed deadline and completion enums. Match unbounded behavior against
`WaitDeadline::Forever` explicitly, rather than treating every non-finite
variant as unbounded. Keep final input staging at the completion boundary,
after callback-producing service. Continue to bound callback batches so a
self-rescheduling timer cannot exclude pending commands.

`ReadCharWaitMode::{Unbounded, Timed { deadline }}` chooses
`IdleTransitionPolicy::{Manage, Preserve}` once. The policy is required by
input-drain handlers, queued help and unified wait special-event service,
covering timeout, real input and ignored-event exits. A wait carries it
separately from its physical deadline: an unbounded read can temporarily wait
to an autosave or display-maintenance deadline without becoming a timed Lisp
read. No snapshot restores state over arbitrary nested callback actions.

This removes unconditional idle changes from these read paths and makes new
handler call sites choose a typed policy explicitly. Broader replacement of
the generic wait request with distinct command/process wait types is a future
option if new callers introduce invalid policy combinations; the present
private constructors already constrain the active combinations.

## Validation

- Existing wait regressions: **2 / 2 failed before the PR fix** with the
  expected wrong completion reasons (`tmp/verification/wait-baseline-red.log`).
- First timed-read tests: **3 failures / 2 passing controls**, then **5 / 5
  passed** (`tmp/verification/timed-read-red.log`, `timed-read-green.log`).
- Ignored-motion and asynchronous special-input regressions: **2 / 2 failed**
  before propagation (`tmp/verification/timed-read-special-red.log`).
- Redisplay/preliminary-service regression: **1 / 1 failed** before its policy
  handoff (`tmp/verification/timed-read-preliminary-red.log`).
- Final relevant unit suite: **133 / 133 passed**, covering keyboard, timer,
  wait, process-output idleness, both existing completion regressions and all
  eight new timed-read/control cases (`tmp/verification/timed-read-final-green.log`).
- GNU batch probe independently returned `(t nil t nil t)` for real idle
  callback reads with zero and nonzero timeouts.
- Old-runtime TUI and GUI both reproduced idle loss; GNU TUI passed
  (`tmp/idle-output-tui-red-2.log`, `tmp/idle-output-gui-red.log`).
- Live GNU timer oracle family: **12 / 12 passed**, including the actual
  idle-callback timed-read test (`tmp/verification/oracle-final-green.log`).

  (`tmp/idle-output-tui-final.log`). Neo's idle time increased from 1.000249
  to 1.010563 seconds across the timed read, with 20 ordinary timer ticks,
  20 process-output deliveries and a live worker.
- GUI: **1 / 1 passed**, including actual green mode-line pixels

  1.010704 seconds while ordinary timers and process output continued.
- Final development binary and its matching pdump built successfully;
