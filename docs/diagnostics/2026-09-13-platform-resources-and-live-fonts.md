## Scope that GNU actually supports

Resource lookup parity is actionable on both platforms. A GNU-compatible desktop fixed-width-font subscription is not present on either native Windows or Cocoa in this revision. Cocoa's initial AppKit fixed-pitch default, Cocoa font-catalog invalidation, Windows UI fonts, and Linux's opted-in desktop monospace preference are different contracts. Retain an explicit unsupported subscription rather than labeling a new interpretation of these other signals as GNU parity. The existing [Windows](2026-09-13-gnu-windows-default-font.md), [Cocoa](2026-09-13-gnu-macos-default-font.md), and [Linux live settings](2026-09-13-live-desktop-font-settings.md) notes cover the earlier findings.

## Shared public resource semantics

GNU constructs the instance key as `INSTANCE.ATTRIBUTE`, or `INSTANCE.COMPONENT.ATTRIBUTE`; the class key is `CLASS-PREFIX.CLASS`, or `CLASS-PREFIX.CLASS.SUBCLASS`. Prefixes come from `x-resource-name` and `x-resource-class`. COMPONENT and SUBCLASS must both be present or both absent. Arguments are checked as strings. Resource-name validation replaces invalid bytes with underscores, or replaces a largely invalid name with `emacs`; an invalid resource class becomes `Emacs`. A native result with empty contents becomes Lisp nil. See [frame.c:6177](/home/exec/Projects/github.com/emacs-mirror/emacs/src/frame.c:6177) and [frame.c:6265](/home/exec/Projects/github.com/emacs-mirror/emacs/src/frame.c:6265).

Frame creation searches the supplied frame alist, then `default-frame-alist`, then resources. Resource discovery should therefore be available to frame-parameter selection and public queries, rather than be folded into the desktop preference snapshot. See [gui_display_get_arg](/home/exec/Projects/github.com/emacs-mirror/emacs/src/frame.c:6367).

## Windows exact precedence

The resource root is `SOFTWARE\GNU\Emacs`. A resource is a named registry **value** directly below that key, not a subkey per resource. Lookup order is:

1. Explicit in-memory RDB instance key, then class key.
2. If `inhibit-x-resources` is non-nil, stop with no result.
3. HKCU instance key, then HKCU class key.
4. HKLM instance key, then HKLM class key.
5. GNU's built-in Windows color resources, searched by instance key only.

The registry accepts `REG_SZ` only; a value of another type falls through. A valid empty `REG_SZ` wins native lookup and later becomes Lisp nil; it does not continue to class/HKLM. HKCU class beats HKLM instance. In-memory keys are case-insensitive exact matches, matching registry case behavior; this is not a full Xrm wildcard matcher. Sources: [w32reg.c:29](/home/exec/Projects/github.com/emacs-mirror/emacs/src/w32reg.c:29), [w32reg.c:61](/home/exec/Projects/github.com/emacs-mirror/emacs/src/w32reg.c:61), and [w32reg.c:78](/home/exec/Projects/github.com/emacs-mirror/emacs/src/w32reg.c:78).

`-Q` suppresses registry and built-in defaults, but does not suppress already supplied RDB entries because they are consulted first. The RDB parser removes ASCII spaces before/in the option and before the value; trailing value whitespace survives, and the first matching entry wins. See [w32_get_string_resource](/home/exec/Projects/github.com/emacs-mirror/emacs/src/w32reg.c:145) and [w32_make_rdb](/home/exec/Projects/github.com/emacs-mirror/emacs/src/w32term.c:7849).

For initial fonts, explicit frame/default-alist fonts and `font`/`Font` resources precede the ordered `Courier New-10`, Courier XLFD, Fixedsys XLFD, Fixedsys fallback chain. Those fallbacks remain platform defaults, never system-font preferences. See [w32_default_font_parameter](/home/exec/Projects/github.com/emacs-mirror/emacs/src/w32fns.c:6205).

Implementation guidance: a read-only native adapter can open each hive, query the two complete value names, and return an owned string. Use a scoped key handle. A Unicode implementation must handle length in bytes, buffer growth, and strings lacking a terminating NUL; `RegQueryValueExW` does not guarantee termination. Reject other types and do not expand environment variables. Microsoft documents these constraints in [RegQueryValueExW](https://learn.microsoft.com/en-us/windows/win32/api/winreg/nf-winreg-regqueryvalueexw). Avoid hard-coding a different registry view from the process's native view without a separate compatibility decision.

## Cocoa exact semantics

`ns_get_string_resource` ignores the instance name and RDB. It takes the full class key and strips the literal, case-sensitive leading `Emacs.` if present, then queries `[[NSUserDefaults standardUserDefaults] objectForKey:...]`. Thus the ordinary font resource key is `Font`; a custom `Other` class prefix produces `Other.Font`, not `Font`. Inhibition stops lookup before accessing defaults. See [nsfns.m:2546](/home/exec/Projects/github.com/emacs-mirror/emacs/src/nsfns.m:2546).

GNU stringifies the returned object with Objective-C `%@`; it is not restricted to NSString values. It then converts any case-insensitive `YES` prefix to `true`, and any `NO` prefix to `false`. Consequently `YESplease` and `Nothing` normalize too. These unusual details require oracle coverage rather than replacing the code with a conventional exact boolean parser. Empty final results become nil in the shared query. See [ns_get_defaults_value](/home/exec/Projects/github.com/emacs-mirror/emacs/src/nsfns.m:1886) and [ns_get_string_resource](/home/exec/Projects/github.com/emacs-mirror/emacs/src/nsfns.m:2546).

The direct `ns-get-resource` builtin queries NAME without that class normalization. Its OWNER argument is effectively ignored by the implementation. `ns-set-resource` likewise writes/removes NAME in standard defaults; it does not target a domain named by OWNER. The direct getter does not apply the generic getter's empty-string or YES/NO normalization. See [nsfns.m:1897](/home/exec/Projects/github.com/emacs-mirror/emacs/src/nsfns.m:1897).

Use standard UserDefaults search semantics, not a manually opened plist. Current Apple documentation orders supported domains as managed, argument, educational managed, app, suite, global, registration; availability varies by process/device. The app domain follows the application identity. Reading `org.gnu.Emacs` explicitly from Neomacs would be an additional compatibility/import choice, not equivalent to calling standard defaults in the current application. See [UserDefaults domains](https://developer.apple.com/documentation/foundation/userdefaults?language=objc); GNU's bundle declares [org.gnu.Emacs](/home/exec/Projects/github.com/emacs-mirror/emacs/nextstep/templates/Info.plist.in:647).

Foundation lists NSUserDefaults as thread-safe. A narrow direct query on the evaluator's host adapter can therefore use an autorelease pool and return an owned Rust string without moving an AppKit object across threads. Keep native AppKit font/event work under the existing main-thread ownership. Apple's [thread safety summary](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/Multithreading/ThreadSafetySummary/ThreadSafetySummary.html) distinguishes these guarantees; it does not say every AppKit class is main-thread-only.

## Why the requested live subscriptions need a different specification

Windows forwards `WM_SETTINGCHANGE` to its Lisp thread, where only wheel-scroll-line changes are handled. No font-following behavior appears there. `WM_FONTCHANGE` describes changes to the font-resource pool, not a preferred document font. `NONCLIENTMETRICS` exposes caption/menu/status/message fonts, not a fixed-width document preference. Sources: [w32fns.c:5655](/home/exec/Projects/github.com/emacs-mirror/emacs/src/w32fns.c:5655), [w32term.c:5240](/home/exec/Projects/github.com/emacs-mirror/emacs/src/w32term.c:5240), [WM_FONTCHANGE](https://learn.microsoft.com/en-us/windows/win32/gdi/wm-fontchange), [NONCLIENTMETRICS](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-nonclientmetricsw).

Cocoa reads `userFixedPitchFontOfSize:-1` for its initial fallback; it has no corresponding desktop-font config event. `changeFont:` is the active font-panel selection callback. Its Core Text registered-font notification callback invalidates family/available-family caches only. See [nsfns.m:1322](/home/exec/Projects/github.com/emacs-mirror/emacs/src/nsfns.m:1322), [nsterm.m:7053](/home/exec/Projects/github.com/emacs-mirror/emacs/src/nsterm.m:7053), and [macfont.m:1082](/home/exec/Projects/github.com/emacs-mirror/emacs/src/macfont.m:1082).

Apple does provide [setUserFixedPitch](https://developer.apple.com/documentation/appkit/nsfont/setuserfixedpitch(_:)), whose nil argument removes the application-domain default. That does not establish a cross-process desktop preference subscription contract. Apple's [registered-font notification](https://developer.apple.com/documentation/coretext/kctfontmanagerregisteredfontschangednotification) is about font registrations and distinguishes local process scope from distributed session/user scope. Neither is evidence that GNU dynamically changes existing document fonts.

If a separate product feature later follows Emacs resource edits, Windows offers `RegNotifyChangeKeyValue`: open with KEY_NOTIFY, rearm after each event, use a persistent owner thread or `REG_NOTIFY_THREAD_AGNOSTIC`, and distinguish shutdown/key-close signals from value changes. Duplicate registrations before completion leak waits. See [Microsoft's contract](https://learn.microsoft.com/en-us/windows/win32/api/winreg/nf-winreg-regnotifychangekeyvalue). This would monitor configuration resources, not a Windows system monospace preference.

For Cocoa defaults, `NSUserDefaults.didChangeNotification` covers writes in the current process and arrives on its writing thread; Apple explicitly recommends KVO to observe edits from other processes. See [didChangeNotification](https://developer.apple.com/documentation/foundation/userdefaults/didchangenotification). A retained observer needs explicit lifecycle removal and delivery to the owning native thread before AppKit queries. No documented stable preference-key mapping from this notification to the user fixed-pitch font was established here; do not guess private `NSUserFixedPitchFont` keys or promise their cross-process behavior.

## Neomacs implementation seams and native tests

At the inspected checkpoint, [FontDefaultsObserver](../../crates/neomacs-display-runtime/src/font_defaults/mod.rs) has a Linux subscription and explicit unsupported cases elsewhere. [GuiFontDefaults](../../crates/neomacs-display-runtime/src/font_defaults/policy.rs) deliberately returns no SystemFonts for Cocoa/Windows. Preserve that separation. [x-get-resource](../../crates/neovm-core/src/emacs_core/display/display/mod.rs) currently returns nil for an active GUI; [internal-face-x-get-resource](../../crates/neovm-core/src/emacs_core/display/xfaces/mod.rs) is also a nil stub. The host has no resource-query operation, so adding only a startup candidate would leave public and later-frame resource behavior incomplete.

Recommended vertical slice: implement full-key construction and validation at the Lisp boundary, a narrow host resource query returning an owned optional string, and native Cocoa/Windows lookup adapters. Keep backend fallback selection unchanged; let resource font choices flow through existing frame/default-face realization. Establish a failing public resource/initial-frame oracle on each native platform before extending the interface to unrelated resources or resource-edit following.

Useful controls are instance/class precedence, HKCU-class versus HKLM-instance, wrong type, empty value, Unicode font names, inhibition, explicit alist font override, later frame creation, Cocoa custom class prefix, Cocoa non-string defaults, and direct-versus-generic getter normalization. Separate native API adapter tests from GNU GUI oracle evidence.

For Windows adapter integration, a dedicated process can remap predefined roots to temporary test keys via [RegOverridePredefKey](https://learn.microsoft.com/en-us/windows/win32/api/winreg/nf-winreg-regoverridepredefkey). This affects only that process and is not inherited as a settings fixture by a separately launched GNU editor. Public GNU tests on disposable native CI should use unique resource names and restore exactly what they changed. Do not point normal workstation tests at the user's existing Emacs font values. Cocoa adapter tests can use a temporary defaults domain or volatile argument domain, but a suite object alone does not prove standard-default lookup in an unmodified GNU GUI. Use a disposable native CI account/application identity for that oracle, preserve/restore test values, and record the actual domain used.

The existing [tmp_mac_test.yml](../../.github/workflows/tmp_mac_test.yml) builds a fresh release and captures a GUI snapshot/readback; it does not compare GNU font/resource behavior. [ci.yml](../../.github/workflows/ci.yml) already has native macOS/Windows runners, Windows font-backend tests, and fresh release jobs. Extend targeted jobs with the resource oracle and explicit font/geometry assertions; do not call compilation, batch execution, or a snapshot alone presentation-confirmed GUI parity. Rebuild through `cargo xtask fresh-build`; use `cargo nextest`, never `cargo test`. Native CI results, unavailable GNU binaries, runner GUI restrictions, and platform feature absence must be recorded separately.
