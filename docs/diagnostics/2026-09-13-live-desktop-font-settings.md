## Isolated backend

`GSETTINGS_BACKEND` selects the default settings backend. For each GUI test, give the editor and its separate `gsettings` writer the same private `XDG_CONFIG_HOME`, `GSETTINGS_BACKEND=keyfile`, and schema fixture. Set these on child-process environments before startup. This preserves the approved public settings/Lisp seam. Backend selection is documented by [GIO](https://docs.gtk.org/gio/class.SettingsBackend.html).

The keyfile backend stores values at `$XDG_CONFIG_HOME/glib-2.0/settings/keyfile`, uses `/` as its root, and creates file/directory monitors. External changes reload the file, compare old/new keys, and notify settings clients. Values use serialized GVariant syntax; the interface-schema group corresponds to `org/gnome/desktop/interface`. File deletion is deliberately ignored, so reset values through `gsettings reset` rather than deleting the file. System defaults/locks can still come from `/etc/glib-2.0/settings`; private XDG config does not isolate that directory. Check writer success and observed values. These details follow [GLib's keyfile backend implementation](https://gnome.pages.gitlab.gnome.org/glib/coverage/gio/gkeyfilesettingsbackend.c.gcov.html).

Inference for test sequencing: seed the backend before launching the editor; wait for the editor's public initial-state readiness; write one change; wait for its public query and frame/face results. A successful writer process only proves the write, not that the editor consumed it. Changes can be coalesced, so a duplicate-write check should use a subsequent distinct application-font change as an observable barrier before checking that document-font hooks/geometry stayed unchanged. Avoid assuming every write produces exactly one native callback.

## Context ownership and initialization order

Settings signals are dispatched through the thread-default `GMainContext` active when the Settings object is constructed. A missing schema is a constructor error, so preserve optional schema lookup before construction. See [Settings.new](https://docs.gtk.org/gio/ctor.Settings.new.html).

Connect relevant `changed` handlers **before** the first read of each watched key. GIO only emits `changed` for a key read at least once while a handler was connected. The callback reports a potential change; reread the value and compare it with the cached typed value before emitting a semantic observation. See [Settings::changed](https://docs.gtk.org/gio/signal.Settings.changed.html).

There are two ownership layers. A Settings object selects its dispatch context, while its backend can already exist: GLib caches the default backend for the entire process lifetime. See [g_settings_backend_get_default](https://raw.githubusercontent.com/GNOME/glib/main/gio/gsettingsbackend.c). File-monitor signals use the monitor's construction context, as documented by [FileMonitor](https://docs.gtk.org/gio/class.FileMonitor.html).

**Implementation inference:** constructing a startup snapshot on the editor thread, dropping it, then creating a live Settings object on a private worker can strand keyfile monitoring on the original unserviced context. Construct startup discovery and the retained subscription together on the context that will actually run. A separate first-use call can otherwise initialize the singleton too early. Dropping a subscription does not imply destruction of GLib's process-global default backend or all its native monitors.

## Rust 0.22.8 lifecycle options

The inspected bindings support a single worker that creates a private context, uses `with_thread_default` across initialization and the loop, and owns Settings plus signal IDs until shutdown. `with_thread_default` acquires the context and releases/restores it with guards, including during panic. `connect_changed` accepts a local `'static` callback; do not move Settings or Lisp values through the editor transport. Sources: [main_context.rs](/home/exec/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/glib-0.22.8/src/main_context.rs:150), [settings.rs](/home/exec/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/gio-0.22.8/src/auto/settings.rs:509).

**Recommended lifecycle:** let the observer return its initial typed font defaults, a receiver of owned `SystemFonts` observations, and a worker guard. The worker constructs Settings under its private context, connects before reading, returns initial facts through the startup rendezvous, then calls blocking `context.iteration(true)` while an atomic stop flag is unset. The guard sets the flag before calling `context.wakeup`, then joins. GLib explicitly documents this atomic termination pattern: a wakeup when the context is not blocked makes its next iteration return without blocking, closing the check-before-iteration race. See [MainContext.wakeup](https://docs.gtk.org/glib/method.MainContext.wakeup.html). A false iteration result means no sources were dispatched, which is normal after an interrupted wait; it is not an error. See [MainContext.iteration](https://docs.gtk.org/glib/method.MainContext.iteration.html).

Implementation inference: keep `with_thread_default` alive for that complete worker scope, make callbacks perform nonblocking delivery, and let evaluator-owned teardown stop/join the worker before dropping delivery ownership. Unsupported adapters should supply a disconnected/disabled observation path that does not make an input selector spin. Initial AppKit discovery can remain on the main thread; Linux's worker is an adapter detail. There is no need for a periodic timeout, a MainLoop, or another shutdown thread in this design. The lifecycle guarantee is that subscription callbacks and the worker have stopped; the default backend remains GLib-owned process state.

`MainLoop` is `Send + Sync`, so a controller can retain a clone to request termination, then join the worker. However, a direct `quit` immediately after initialization readiness can occur before `run`; `run` sets the running flag again. Use a shutdown source attached to the owned context or acknowledge readiness from an already dispatched source. The former avoids requiring a startup delay. Evidence: [Rust MainLoop](/home/exec/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/glib-0.22.8/src/auto/main_loop.rs:41), [GLib run/quit implementation](https://raw.githubusercontent.com/GNOME/glib/main/glib/gmain.c).

`MainContext::invoke` can execute synchronously when context ownership permits, so do not assume it always queues. An explicit `idle_source_new(...).attach(Some(&context))` makes dispatch ownership clear. It accepts a `Send` closure and can capture a MainLoop clone. See [invoke](https://docs.gtk.org/glib/method.MainContext.invoke.html) and [Rust source creation](/home/exec/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/glib-0.22.8/src/source.rs:753).

After loop return, disconnect handlers on the worker, release Settings, and join before dropping editor delivery ownership. Already-dispatched sources can still execute after `quit`, per [MainLoop.quit](https://docs.gtk.org/glib/method.MainLoop.quit.html). `SourceId::remove` targets the global default context; for an explicitly attached private-context source, retain its `Source` and call `destroy` if cancellation is needed. See [SourceId](/home/exec/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/glib-0.22.8/src/source.rs:17), [Source.destroy](/home/exec/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/glib-0.22.8/src/auto/source.rs:42), and [ObjectExt.disconnect](/home/exec/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/glib-0.22.8/src/object.rs:3063).

## GNU behavior to assert through the GUI oracle

| Case | Source-derived expected behavior |
| --- | --- |
| Monospace preference changes while opted out | Cached `font-get-system-font` changes; existing frames remain unchanged. |
| Opted in | Native handling queues `config-changed-event`; Lisp checks the option again before applying. |
| Existing frame has an explicit font | The live handler has no explicit-font veto; it applies the new font to all frames on the event's display. |
| Future frames | The live call updates the session's Custom default-face font attributes. Test an ordinary new frame separately from a new frame with an explicit font argument. |
| Application preference changes | `font-get-system-normal-font` changes; `font-name` has no font-changing branch in this Lisp handler. |
| Identical monospace string repeated | Native cache comparison returns before queuing a config event. No dynamic font call follows from that duplicate. |
| Opt-out then opt-in without another native change | Assigning the variable alone does not replay a skipped event in these paths. Test this distinction if toggling is included. |
| Geometry on live application | The handler passes nil KEEP-SIZE, meaning preserve rows/columns, with pixel dimensions following realized font metrics. |

The cache updates, duplicate suppression, and native opt-in gate are in [xsettings.c:111](/home/exec/Projects/github.com/emacs-mirror/emacs/src/xsettings.c:111). An oracle should record system queries, default face, frame font, rows/columns and pixel dimensions, plus `after-setting-font-hook` counts around duplicates. Those public observations distinguish refreshed preferences from font application; source inspection alone cannot establish Neomacs realization or Wayland presentation correctness.
