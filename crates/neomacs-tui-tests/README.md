# `neomacs-tui-tests`

End-to-end TUI parity harness comparing Neomacs (`-nw`) against the pinned GNU Emacs oracle over real pseudo-terminals.

## Harness Invariants

Every TUI test must make explicit **which Emacs** and **which terminal database** it ran against:

1. **Attested GNU Emacs oracle only.** Resolve GNU Emacs via `neomacs_tui_tests::oracle::gnu_oracle_program()` (and record `gnu_oracle_stamp()` in diagnostic output). Never hardcode `PathBuf::from("emacs")` or silently fall back to an unattested `PATH` binary or custom env var (`NEOMACS_GNU_EMACS_BINARY`); if the pinned oracle (`parity-reference.toml` / `NEOVM_FORCE_ORACLE_PATH`) is unavailable or non-canonical, the test must fail loudly. Every test file in `crates/neomacs-tui-tests` follows this invariant (#845), enforced by the fail-closed regression guard in `src/oracle_guard_test.rs`.
2. **Explicit terminal database (`TERMINFO`).** Older host terminfo databases (such as macOS's ncurses 5.7 `/usr/share/terminfo`) omit newer entries like `alacritty` and `contour`. When a test requires a `TERM` value absent from the host database, compile the real upstream terminfo source via `tic` into an isolated `TERMINFO` directory (never fabricate a mutant alias from a different terminal type) and report the `terminfo` source in test diagnostics.
3. **Non-blocking PTY master writes.** Both `PtyOutputPump` (`src/pty_output/owner.rs`) and auxiliary non-blocking PTY masters (`write_all_nonblocking_pty` in `src/pty_output.rs`, used by `AuxiliaryTty::send` in `tests/tty_relay.rs`) loop across POSIX short writes, `EINTR`, and `WouldBlock`/`EAGAIN` (waiting on `POLLOUT` within a bounded deadline) while keeping `EIO`/`BrokenPipe`/`WriteZero` fatal and preserving exact committed-prefix accounting.
4. **Load-independent synchronization (no quiet-box barrier).** The 22 gate TTY rows — 15 in `neomacs-tui-tests --test tui` (`test(/tty_mode_|suspend_emacs_|secondary_tty|tty_input|tty_relay/)`) and 7 in `neomacs --test neomacs_integration` (`test(/tty/)`) — were measured across 5 consecutive full runs (**110/110 passed, 0 failures, 0 retries**) at sustained `/proc/loadavg` `25.5`–`60.6` on a 32-core Linux host (`9ca34ffd1c`, attested `linux-gtk3` GNU Emacs 31.1). They synchronize on state/receipt markers (PTY output markers, `waitpid(WUNTRACED)` stop/resume signals, result files) and do **not** require a quiet machine; re-measure under load before re-introducing any quiet barrier. Watch items if host load climbs even higher: `neomacsclient_tty_forwards_resize_to_the_server_process` (`0.381s` max at load `60.6` vs its `2s` deadline) and `tty_mode_strings_emitted_on_suspend_tty_and_resume_tty_like_gnu` (`24.141s` max total across sequential GNU + Neomacs at load `58` vs `8s`/`10s` inner wait caps).
5. **Cell-level display assertion ratchet (`src/cell_assertion_guard_test.rs`).** Any TUI test whose subject is a face, cursor, or chrome element (menu bar, tab bar, mode line, line-number gutter) must assert terminal cell attributes/colors against GNU (`assert_pair_exact_display`, `PackageTuiPair::assert_display`, or `RawTerminalSnapshot` / `assert_raw_terminal_snapshots_eq`), not plain text alone. Enforced by `cell_assertion_guard_test::cell_assertion_ratchet_matches_pinned_inventory` via exact exception pins (`text_and_face`, `text_only`, `blocked_chrome_divergence`), typed `NON_CELL_ALLOWLIST` entries, and non-shrinking floors on `total` and `text_and_cells` (`min_total`, `min_text_and_cells`) so adding new strong `TextAndCells` tests passes freely without crying wolf while silent test loss or new/downgraded exceptions fail loudly:
   - **Baseline audit on `c2ab78b0e9`** (all 1,164 integration `#[test]` rows across 125 files under `tests/`, including 1 `doom-repro`-gated row; plus 134 library unit tests in `src/`): **990 / 1,164 (85.1%)** `TextAndCells`, **2 / 1,164 (0.2%)** `TextAndFace` (`bidi_paragraph_direction_tui_oracle.rs`, `tty_color_index.rs::face_colours_reach_the_wire_as_the_index_lisp_computed`), **172 / 1,164 (14.8%)** `TextOnly` (including `display_line_numbers.rs::narrowed_gutter_width_and_painted_prefix_match_gnu_matrix`, which previously dumped `RawTerminalSnapshot` only to a debug artifact file without asserting on it).
   - **Pinned counts (`CELL_ASSERTION_PINS`)**: **1,004 / 1,166 (86.1%)** `TextAndCells` (after converting 13 attribute-subject rows across `display_line_numbers.rs` [3], `issue_140_hscroll.rs` [2], `issue_445.rs` [2], `issue_470.rs` [1], `minibuffer_barrier.rs` [1], `redisplay_transitions.rs` [4], plus fixing the live TTY `set-frame-size` divergence and upgrading `treesit_debug_mode_line.rs` [1]), **2 / 1,166 (0.2%)** `TextAndFace` (**1,006 / 1,166 = 86.3%** asserting attributes), and **160 / 1,166 (13.7%)** `TextOnly` (`LispOracleOrProperty` 100, `BufferTextOrWorkflow` 23 [including the 2 text-column rows in `issue_702_truncated_margin_parity.rs`], `PtyStreamOrLifecycle` 22, `EventOrProcessRouting` 15, `BlockedChromeDivergence` 0).
   - **Documented follow-ups (not widened)**:
     - `tests/menu_bar.rs` (2 rows) and `tests/tty_menu_grid_oracle.rs` (1 row) are counted in `TextAndCells` because they call `assert_pair_exact_display` after `C-g` closes the F10 drop-down menu, but their open-menu checkpoints still assert text only.
